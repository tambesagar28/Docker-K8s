By the end of this lesson, you should be able to:

- Create multiple containers from the same image.
- Verify container states using Docker commands.

## 1. Understanding the Container Lifecycle

A Docker container is created from an image and can move through different lifecycle states.

The most common operations are:

- **Create:** Create a container without starting its main process.
- **Start:** Start an existing stopped container.
- **Run:** Create a new container and start it.
- **Stop:** Gracefully stop a running container.
- **Restart:** Stop and start the same container.
- **Remove:** Delete a stopped container.

### Simplified Container Lifecycle

```text
             docker create
                    |
                    v
                 Created
                    |
                    | docker start
                    v
                 Running
                /   |   \
               /    |    \
      docker stop   |   Process exits
             |      |
             v      |
          Stopped <-+
             |
             | docker start
             v
          Running

Stopped Container
       |
       | docker rm
       v
     Removed
```

**Important:** A container can also enter states such as `created`, `paused`, `restarting`, `exited`, or `dead`, depending on the situation.

## 2. Running vs. Stopped Containers

### Running Container

A running container has its main process executing.

Example:

```bash
docker run -d --name day2-nginx nginx:alpine
```

Verify:

```bash
docker ps
```

The container should appear in the output with a status similar to:

```text
Up 10 seconds
```

### Stopped Container

A stopped container has no running main container process, but its container object still exists.

Stop the container:

```bash
docker stop day2-nginx
```

Now execute:

```bash
docker ps
docker ps -a
```

Observe the difference:

| Command | Result |
|---|---|
| `docker ps` | Does not display the stopped container. |
| `docker ps -a` | Displays the stopped container. |

A stopped container can be started again without creating a new container.

## 3. Container ID vs. Container Name

Every Docker container receives a unique container ID.

You can also assign a human-readable name using the `--name` option.

Example:

```bash
docker run -d --name day2-nginx nginx:alpine
```

Here:

- **Container name:** `day2-nginx`
- **Container ID:** A unique identifier generated by Docker.

### Display Container IDs and Names

```bash
docker ps
```

Display only container IDs:

```bash
docker ps -q
```

Display container IDs and names:

```bash
docker ps --format "table {{.ID}}\t{{.Names}}\t{{.Status}}"
```

Inspect the container ID:

```bash
docker inspect --format '{{.Id}}' day2-nginx
```

### Why Use Container Names?

Container names are easier to remember than long IDs.

For example:

```bash
docker stop day2-nginx
docker start day2-nginx
docker logs day2-nginx
```

You can use a container name or an appropriate container ID with Docker commands.

**Important:** Container names must be unique among existing containers. A name cannot be reused while a container with that name still exists.

## 4. Practical Exercise 1 — Create and Run an NGINX Container

### Step 1: Pull the Image

```bash
docker pull nginx:alpine
```

This downloads the image if it is not already available locally.

### Step 2: Create and Start a Container

```bash
docker run -d --name day2-nginx -p 8081:80 nginx:alpine
```

Explanation:

| Option | Purpose |
|---|---|
| `-d` | Runs the container in detached mode. |
| `--name day2-nginx` | Assigns a name to the container. |
| `-p 8081:80` | Maps host port 8081 to container port 80. |
| `nginx:alpine` | Specifies the image. |

### Step 3: Verify the Container

```bash
docker ps
docker images
```

Open the following URL:

http://localhost:8081

You should see the NGINX welcome page.

---

## 5. Practical Exercise 2 — Stop a Container

Stop the running container:

```bash
docker stop day2-nginx
```

Verify:

```bash
docker ps
docker ps -a
```

### Expected Observations

- The container disappears from the default `docker ps` output.
- The container remains visible in `docker ps -a`.
- Its status should indicate that it has exited.
- The NGINX image remains available locally.

Check the exact status:

```bash
docker inspect --format '{{.State.Status}}' day2-nginx
```

Expected output:

```text
exited
```

The container has stopped, but it has not been removed.

---

## 6. Practical Exercise 3 — Start a Stopped Container

Start the existing container:

```bash
docker start day2-nginx
```

Verify:

```bash
docker ps
```

Open the browser:

http://localhost:8081

The NGINX welcome page should be accessible again.

### Important Concept

`docker start` starts an existing container. It does not create a new container.

The container retains its identity and configuration when it is stopped and started again.

---

## 7. Practical Exercise 4 — Restart a Container

Restart the container:

```bash
docker restart day2-nginx
```

Verify:

```bash
docker ps
docker inspect --format '{{.State.Status}}' day2-nginx
```

The container should return to the running state.

### What Does Restart Mean?

Restarting a container stops and starts the same container.

It does not create a new container or delete the image.

By default, Docker attempts to stop the container gracefully before starting it again.

---

## 8. Practical Exercise 5 — Remove a Container

First, stop the container:

```bash
docker stop day2-nginx
```

Remove it:

```bash
docker rm day2-nginx
```

Verify:

```bash
docker ps -a
docker images
```

### What Should You Observe?

- The `day2-nginx` container no longer appears in the container list.
- The `nginx:alpine` image remains available locally.
- You cannot start the removed container because the container object no longer exists.

**Key concept:** Removing a container does not automatically remove the image used to create it.

---

## 9. Practical Exercise 6 — Create a New Container from the Same Image

Even after removing the previous container, you can create a new container using the same image.

Run:

```bash
docker run -d --name day2-nginx-new -p 8082:80 nginx:alpine
```

Verify:

```bash
docker ps
docker images
```

Open:

http://localhost:8082

The NGINX welcome page should appear.

Compare the new container ID with the ID of the previous container if you recorded it.

The new container has a different identity, even though both containers were created from the same image.

### Compare Two Containers from One Image

You can also run two containers simultaneously using different host ports:

```bash
docker run -d --name web-one -p 8083:80 nginx:alpine
docker run -d --name web-two -p 8084:80 nginx:alpine
```

Verify:

```bash
docker ps
```

Open both URLs:

- http://localhost:8083
- http://localhost:8084

Both containers use the same image but have separate container identities and runtime configurations.

## 10. `docker run` vs. `docker create` vs. `docker start`

These commands perform different operations.

| Command | What it does |
|---|---|
| `docker run IMAGE` | Creates a new container and starts it. |
| `docker create IMAGE` | Creates a container without starting its main process. |
| `docker start CONTAINER` | Starts an existing stopped or created container. |
| `docker stop CONTAINER` | Gracefully stops a running container. |
| `docker restart CONTAINER` | Stops and starts the same container. |
| `docker rm CONTAINER` | Removes a stopped container. |

### Example: Use `docker create`

```bash
docker create --name created-nginx nginx:alpine
```

Inspect its state:

```bash
docker inspect --format '{{.State.Status}}' created-nginx
```

Expected output:

```text
created
```

Start it:

```bash
docker start created-nginx
```

Verify:

```bash
docker ps
```

The container should now be running.

Clean up this additional container when finished:

```bash
docker stop created-nginx
docker rm created-nginx
```

## 11. Important Concept — What Happens to the Image?

Suppose you execute:

```bash
docker pull nginx:alpine
docker run -d --name web-test nginx:alpine
docker stop web-test
docker rm web-test
```

The result is:

- The container is removed.
- The image remains available locally.
- You can create another container using the same image.

To remove the image explicitly, you can use:

```bash
docker rmi nginx:alpine
```

This succeeds only if the image is not still referenced by containers or otherwise prevented from being removed.

**Do not run the image-removal command unless you intend to remove the local image.** It is not required for this lesson.

## 12. Day 2 Command Reference

| Command | Purpose |
|---|---|
| `docker run -d IMAGE` | Creates and starts a container in detached mode. |
| `docker create IMAGE` | Creates a container without starting it. |
| `docker ps` | Lists running containers. |
| `docker ps -a` | Lists all containers. |
| `docker ps -q` | Lists IDs of running containers. |
| `docker stop CONTAINER` | Stops a running container. |
| `docker start CONTAINER` | Starts an existing container. |
| `docker restart CONTAINER` | Restarts an existing container. |
| `docker inspect CONTAINER` | Displays detailed container information. |
| `docker rm CONTAINER` | Removes a stopped container. |
| `docker images` | Lists local images. |
| `docker rmi IMAGE` | Removes a local image when permitted. |
